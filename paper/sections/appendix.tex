\section{Hyperparameter tuning}
\label{app:tuning}

All methods share one PPO configuration, tuned for IPPO alone on
\texttt{simple\_spread} with a separate tuning seed (1000). The criterion was
self-play return on the first 500 test-range evaluation episodes, which include
the 240 test episodes used for every reported return; only IPPO runs on the
tuning seed were scored. We varied the learning rate ($3{\times}10^{-4}$ to
$2{\times}10^{-3}$), epochs per update (5--15), minibatches (4--16), episodes per
update (32--256) and the entropy coefficient (0 or 0.01); the full table is in
\texttt{docs/tuning.md}. Each configuration was run with a single seed. With
the chosen configuration, the standard deviation of IPPO's self-play return
across the ten main seeds is \SpreadIPPOSPsd{} on \texttt{simple\_spread}, so
the sweep can only rule out configurations that are clearly worse; its top six
configurations are within noise of each other, and the chosen configuration's
tuning run (\TuneSpreadChosen{} after $3\times10^6$ steps) was a favourable
seed. On \texttt{simple\_adversary}, the configuration tuned on
\texttt{simple\_spread} scored \TuneAdversaryChosen{} against
\TuneAdversaryOther{} for the earlier default (single seeds, each against its
own adversary; seed standard deviation \AdversaryIPPOSPsd{} in the main
suite), so it may be slightly suboptimal for that environment. Every \texttt{simple\_spread} run was still
improving at the $5\times10^6$-step budget: over the last million steps the
training return rose in \SpreadSlopePos{} of \SpreadSlopeN{} runs, with method
means from \SpreadSlopeLo{} to \SpreadSlopeHi{} return points per million steps.
On \texttt{simple\_adversary} the training return, measured against each run's
co-trained adversary, was flat (method means from \AdversarySlopeLo{} to
\AdversarySlopeHi{}; \AdversarySlopePos{} of \AdversarySlopeN{} runs rising).

\section{Environment re-implementation}
\label{app:env}

Our batched environments follow the \texttt{mpe2} reference implementation of
\texttt{simple\_spread\_v3} (local reward ratio 0.5, agent radius 0.15, soft
contact forces) and \texttt{simple\_adversary\_v3} ($N=3$ good agents, one
adversary, shaped distance rewards), with discrete actions and 25-step
episodes. Resets reproduce the reference random-number draws exactly. The test
suite steps both implementations side by side under random actions from
several seeds and checks that observations agree to $10^{-5}$ and rewards to
$10^{-6}$ at every step. Stepping 128 episodes at a time, the batched
\texttt{simple\_spread} runs about $\EnvSpeedup\times$ more environment steps
per second than \texttt{mpe2} stepping one environment at a time
(\texttt{scripts/benchmark\_env.py}). In \texttt{simple\_spread} the agents are
silent, so the two communication entries in each teammate block are always
zero.
