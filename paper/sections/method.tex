\section{Teammate-order invariance and how to obtain it}
\label{sec:method}

\begin{figure}[t]
\centering
\includegraphics[width=\linewidth]{figures/method_overview.pdf}
\caption{\picr. The teammate blocks of an observation are reordered by two
independent random permutations; the shared policy is applied to both views and
the symmetric KL divergence between the two action distributions is added to the
PPO loss. The penalty is used only during training.}
\label{fig:method}
\end{figure}

\paragraph{Setting.}
We consider $n$ cooperating agents that share one policy $\pi_\theta$
(parameter sharing, \citealp{dewitt2020ippo,yu2022mappo}). Agent $i$'s
observation is $o_i = [s_i, u_{i,1}, \dots, u_{i,n-1}]$, where $s_i$ holds the
agent's own features and the environment, and $u_{i,k}$ is a fixed-width block
of features describing the $k$-th other agent (here, its relative position).
Teammates are exchangeable, so for any permutation $\sigma$ of the $n-1$ blocks
the observation $\sigma o_i = [s_i, u_{i,\sigma(1)}, \dots, u_{i,\sigma(n-1)}]$
describes the same situation. A policy is \emph{teammate-order invariant} if
$\pi_\theta(\cdot \mid \sigma o) = \pi_\theta(\cdot \mid o)$ for all $\sigma$.
An MLP over the concatenated observation has no reason to be invariant: the
slot a teammate occupies is determined by agent indices, so the policy can
learn conventions keyed to ``the first teammate''. At deployment every method
sees teammates in the environment's index order.

\paragraph{Methods.}
We compare five ways of handling teammate order, all trained with the same PPO
learner and hyperparameters:
\begin{itemize}[leftmargin=1.3em,itemsep=1pt,topsep=2pt]
\item \textbf{IPPO}: an MLP policy over $o_i$; no invariance.
\item \textbf{\picr} (Fig.~\ref{fig:method}): IPPO plus the training-time penalty
\begin{equation}
\mathcal{L}_{\picr} = \lambda\, \E_{o}\, \E_{\sigma_1,\sigma_2}
\Big[\tfrac12 \KL\big(\pi_\theta(\cdot\mid\sigma_1 o)\,\|\,\pi_\theta(\cdot\mid\sigma_2 o)\big)
   + \tfrac12 \KL\big(\pi_\theta(\cdot\mid\sigma_2 o)\,\|\,\pi_\theta(\cdot\mid\sigma_1 o)\big)\Big],
\end{equation}
with $\sigma_1, \sigma_2$ drawn uniformly and independently per observation in
the PPO batch and gradients flowing through both views. The penalty is zero
exactly when the policy is invariant on the sampled observations. With $n-1=2$
teammate blocks the two permutations coincide with probability $1/2$, so the
expected penalty is $\lambda/2$ times the symmetric KL between the two
orderings. The deployed network is an unchanged MLP, with no extra parameters
and no test-time cost.
\item \textbf{Deep Sets}: each teammate block passes through a shared encoder
$\phi$ (one 64-unit tanh layer), the encodings are mean-pooled, and $\rho$ (two
64-unit tanh layers) maps the agent's own features and the pooled encoding to
the policy head \citep{zaheer2017deepsets}; the critic has its own copy. The
policy is invariant by construction. It is also a different and larger network
than the MLP (Appendix~\ref{app:cost} lists parameter counts), so differences
between Deep Sets and the MLP methods are not attributable to invariance alone.
\item \textbf{Order augmentation}: IPPO where, while acting during training,
every agent's teammate blocks are freshly permuted at every step, and PPO
trains on the permuted inputs. The team's return then depends only on the
order-averaged policy: nothing rewards the policy for agreeing with itself
across orderings, so this does not train toward invariance.
\item \textbf{Order randomization}: in the spirit of Other-Play
\citep{hu2020otherplay}, each agent draws one teammate ordering at the start of
each training episode and keeps it for the whole episode, so teams train with
members whose views order their teammates differently but consistently. A
policy that relies on a convention keyed to teammate slots then miscoordinates
during training. Unlike Other-Play, the transformation applies only to each
agent's view of its teammates, not to actions or the environment.
\end{itemize}
